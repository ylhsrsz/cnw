## 2. 各层级用途说明

### 2.1 根目录

- 存放首页、总模板、页眉页脚规范和目录结构说明；
- 适合作为老师或验收人员的第一入口；
- 有助于在不展开子目录时快速定位全部提交材料。

### 2.2 `task1/`

- 存放 TCP 抓包专项文档；
- 文档中应包含 Task1 的环境、端口、过滤器、关键报文截图、日志对照和结论。

### 2.3 `task2/`

- 存放 UDP 抓包专项文档；
- 文档中应包含握手阶段、可靠传输阶段、重传与 ACK 分析、窗口说明和结论。

### 2.4 `resources/images/`

- `environment/`：环境截图，如网卡选择、Wireshark 界面、终端启动界面；
- `task1/`：Task1 关键报文截图；
- `task2/`：Task2 关键报文截图。

### 2.5 `resources/logs/`

- 存放客户端和服务端运行日志；
- 用于和 Wireshark 时间戳互证；
- 当前目录已经归档现有的 `run_log` 文件。

### 2.6 `resources/pcap/`

- 存放原始抓包文件；
- 建议使用 `pcapng` 格式；
- 不建议只提交截图而缺失原始抓包文件。

### 2.7 `resources/filters/`

- 存放过滤器说明和端口筛选表达式；
- 方便复现实验与验收人员快速查看关键报文。

## 3. 命名规范

建议统一采用“任务 + 内容 + 学号后四位”的命名方式：

- `tcp_packet_capture_2308.md`
- `udp_packet_capture_2308.md`
- `task1_tcp_capture_2308.pcapng`
- `task2_udp_capture_2308.pcapng`
- `task1_handshake_2308.png`
- `task2_retransmit_2308.png`

## 4. 提交建议

1. 先补齐 `pcap` 文件与截图。
2. 再在对应任务说明中插入图片并写明分析。
3. 最后将整个 `提交目录_2308` 压缩提交。
4. 压缩包建议命名为：

```text
20260614-2308-抓包说明提交.zip
```

## 5. 验收视角下的完整性标准

若要满足正式提交和验收查看需求，建议至少具备以下材料：

1. 首页与统一页眉页脚说明；
2. TCP 说明文档；
3. UDP 说明文档；
4. 原始抓包文件；
5. 关键截图；
6. 客户端与服务端日志；
7. 过滤器与端口说明。
